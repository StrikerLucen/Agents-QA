# Testing conventions — {{PROJECT_NAME}}

Numbered, enforceable rules the agents check new tests against. The agents are
regenerated by `/testsquad:upgrade`; this file is not, which is why the rules
live here and not inside an agent.

The SessionStart hook surfaces the first few lines, so keep each rule to one
line and put the rationale in the linked lesson.

1. Tests must run with no DB: mock the data layer completely — `npx vitest run` passes with no services started. (lesson 2026-11-03)
2. Every new test file imports `renderWithProviders` from `test/helpers` — `rg -l renderWithProviders 'src/**/*.test.tsx' | wc -l` → 38 of 41. (lesson 2026-11-07)
3. No `sleep` or fixed timeout in a test, wait on a condition — `rg -n 'setTimeout' test/` → 0. (lesson 2026-10-28)
4. {{RULE, one line, specific and checkable, with the command that checks it}}

## What belongs here

A rule is in the right register when an agent can **check it** and a reviewer can
**fail a PR on it**. "Tests must run with no DB: mock the data layer completely"
is a rule. "Write good tests" is a mood. If you cannot name the command that
would catch a violation, it is not ready to be a rule.

## Where these come from

**These are promoted lessons, not invented rules.** Each traces to a file in
`.testing/lessons/` with the evidence — a command and its real output — that
produced it. A rule with no lesson behind it is someone's preference wearing a
number.

**Promotion requires the user's approval, always.** `/testsquad:learn` proposes;
a human says yes. The reason for the ceremony: every agent reads this file on
every run and never questions it, so a wrong rule is wrong forever and the output
stays confident the whole time.

Retiring a rule means retiring its lesson too, with the command that disproved
it. Never a silent delete.
